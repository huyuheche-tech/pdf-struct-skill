# 检查规则与误报边界

每条检查都对应 `checks.json.errors / warnings` 里的 `code`。**错误不可静默忽略**：
要么改 draft / 改输入，要么在 `result.json.uncertainty` 写明为什么消不掉。

## 1. 硬错误（`status=partial`）

| code | 判据 | 常见误报 | 正确处置 |
|---|---|---|---|
| `missing_entry` | 正文引用（编号 / key / 作者-年份）在文献表里对不上 | 文献表是纯文本段落，解析器没认出条目（这时会同时解析出 0 条） | 补条目（**不能编**）或修正引用；不要为了消错删条目 |
| `unsafe_merge` | draft 提议合并的两条既不同 DOI，也不满足"标题 ≥0.90 + 第一作者同姓" | 两条其实是同一篇但标题差别大（撤稿声明、译名不同） | 撤回提议；确属同一篇就在 `uncertainty.human_review` 说明，人工合并 |
| `field_missing`（severity=error） | `declared_complete` 里的条目缺 author/title/year/source/doi | 把 DOI 缺失当成"无所谓"却仍声明完整 | 从 `declared_complete` 去掉该 key，或补齐字段 |
| `unknown_key` | `merges` 里出现文献表中不存在的 key | key 拼错、大小写不同 | 照文献表的 key 原样写 |

## 2. 警告（可交付，但必须交代）

| code | 判据 | 处置 |
|---|---|---|
| `uncited_entry` | 文献表有条目、正文一处都没引 | 确认是备用文献还是漏引；漏引补 `[n]`，不用就删 |
| `number_gap` | 编号文献表里编号重复，或 1..N 有断号 | 重编号会修正正文；表本身要人看是否漏条 |
| `duplicate_entry` | 已按 DOI 或标题相似度合并 | 看 `basis`；不成立就把 DOI 补全再跑 |
| `field_missing`（severity=warning） | 条目缺字段，参考文献表写 `[TODO: field]` | 回原始文献补；补不到保留 TODO，**不要编** |
| `draft_bad_merge` | `merges` 的元素不是一对 | 改成 `["keyA","keyB"]` |

## 3. 阈值与依据（可复核）

| 判据 | 阈值 | 说明 |
|---|---|---|
| DOI 相同 | 精确相等（忽略大小写与 `https://doi.org/` 前缀） | 最硬的依据，直接合并 |
| 题名数字 | 归一化题名里的数字序列必须完全相同 | `Part 1`/`Part 2`、`GPT-3`/`GPT-4`、`Paper number 1`/`… 2` 一律不合并，哪怕相似度 0.99 |
| 标题相似度 | `difflib.SequenceMatcher` on 归一化标题（小写、去标点、压空格）≥ **0.90** | 低于 0.90 一律不合并，即使看起来很像 |
| 第一作者 | 姓氏相同（`Chen, Wei` / `Wei Chen` / `Chen W` 均可识别） | 姓不同绝不合并 |
| 编号连续 | 正文新编号 1..N，无重复 | `renumber_map` 的 `new` 必须覆盖全部条目 |

合并时的取舍：**类型 J 优先于 C**（期刊版压会议版），其余按"字段更全者优先"，缺的字段从另一条补，
`merged_from` 记下被并掉的 key。所以合并后 `completeness` 可能比任何单条都高——这是合并的价值，
但**不是**编造：只搬条内已有的字段。

## 4. 刻意的取舍（宁可漏报，不误报）

- 只重编号**数字标记** `[1]`/`[2,4]`/`[3-5]`。`\cite{key}` 与 `(Smith, 2020)` 一律不动：
  改 LaTeX key 会破坏编译，改作者-年份会改变语义。
- `[3-5]` 解析成 3/4/5 三个 id；重编号后若连续 ≥3 个会压回 `[a-b]` 形式，否则逐个列出。
- 编号表的作者字段按 `,`/`，`/`;` 切分，因此 `Chen, Wei` 这种"姓, 名"写法会被切成两位作者。
  编号表请用 `Chen W` 形式（GB/T 惯例）。
- 作者-年份匹配要求"第一作者姓氏 + 年份"都对上；`et al.` 不影响匹配，`2019a` 的字母后缀忽略。
- 中文作者按整名匹配（`陈伟` 与 `陈伟, 2019` 能对上），不做姓氏切分。
- `.ris` 没有 key 字段，引擎生成 `risNN` 形式的内部 key；因此 `.ris` 稿请用编号引用（`[1]`），
  用 `\cite{某key}` 会必然对不上（这是输入本身的限制，不是解析失败）。
- 未引条目**排到文献表末尾**而不是删除：静默删除是数据丢失，必须让人看见。

## 5. 检查不到的东西（必须写进 uncertainty）

- 文献是否真实存在、DOI 是否能解析、卷期页是否正确（**不联网**）；
- 正文陈述与所引文献是否一致（"引对了"不等于"引得对"）；
- 作者名拼写是否符合原文；
- 期刊要求的特殊格式（双语对照、`[J/OL]`、DOI 展现方式）；
- 图片/表格内的引用。

以上写在 `result.json.uncertainty.note`，不假装覆盖。
