# 引言四段写法与常见失败模式

## Background：先立"为什么值得做"

- 一段话，三件事：领域价值 → 现有做法 → 仍然存在的代价（标注贵、算力高、泛化差）。
- 每个事实性判断挂引用；不要用"众所周知"。
- 不要在这一段提前宣布贡献。

## Related Work：先分组，再评述

- 2–4 组，组名写"这一类方法做了什么"，例如 `attention-based`、`recurrent-baselines`、
  `prompt-tuning`，不要写 `related studies`。
- 每组 1–2 句：代表工作 + 共同假设 + 局限。局限要能自然导向 Gap。
- 组内 `works` 用文献库里的 key；没有库时也要写 key 形式，便于日后核对。

## Gap：写"别人没做"，不写"我们做了"

- 至少 2 条不同引用支撑，说明这个空白是真实的，不是作者自说自话。
- 好 Gap 具备三个特征：可判定（做没做能查）、有代价（不填会怎样）、可填补（本文能做）。
- 不要写"尚无研究"这种过宽断言；限定到任务、数据、预算。

## Contributions：一条一个动作 + 一个可核验结果

- 3 条左右；动词开头（提出 / 证明 / 构建 / 发布 / 评估）。
- 结果数字必须来自 `evidence.json`；没有数字的贡献写清"在什么条件下验证了什么"。
- `contribution_evidence` 为每条绑定一句材料原句；绑不上就删掉这条贡献。
- 贡献一般是作者判断，可放进 `author_judgment`，但不要用它掩盖"其实没有引用"的背景段。

## 常见失败模式

| 失败模式 | 后果 | 正确做法 |
|---|---|---|
| 正文写 21.0%，材料是 18.4% | `claim_unsupported` | 改回材料值，或换一个材料支持的数字 |
| 贡献写得很漂亮但材料里找不到 | `contribution_unbound` | 补材料原句，或删掉该贡献 |
| Gap 只引 1 篇 | `gap_unsupported` | 再找 1 篇指出同一空白的文献 |
| 相关工作堆成一段没有分组 | `grouping_thin` | 按方法类别拆成 ≥2 组 |
| 引用了库里没有的 key | `citation_unknown` | 改拼写/补条目/删引用，不要伪造 |
| 四段缺一段 | `section_missing` | 补写，别用标题占位 |
