# 锚点规则：章节、段号与引文

## 1. 章节切分

引擎按以下优先级识别标题（`notes_builder.heading_of`）：

1. Markdown 标题：`#`–`######`，级别即 `level`；
2. 编号标题：`1`、`1.1`、`2.3.1`，级别 = 点号数 + 1；标题必须 ≤60 字符、不以句号结尾、首字母大写或中文；
3. 命名单行标题：`Abstract`、`INTRODUCTION`、`Methods`、`Results`、`Discussion`、`Conclusion`、`Limitations`、`摘要`、`方法`、`结果`、`局限` 等（可带冒号）；
4. 行内形式：`Abstract. 正文……`、`摘要：正文……`，标题与正文会被拆开。

**段落以空行分隔**。每个章节内段落顺序编号：

```
s01.p01   s01.p02
s02.p01   s02.p02   s02.p03
```

- `sNN` 是章节序号，`pMM` 是章节内段号，均从 1 开始、两位补零。
- 编号是**位置**编号，不是语义编号：不要为了「看起来整齐」改号。
- 解析时 `s1.p2`、`s01.p02`、`S01.P02` 都归一为 `s01.p02`，写错零填充不会误判。

## 2. 锚点写法

```
s03.p02            # 整段
s03.p02@118-176    # 段内字符区间（相对该段文本，0 起）
```

`@start-end` 可选。引擎校验的是 **quote 能否在该段文本中找到**；区间只用于给人回查，
不参与通过/失败判定，因此不要用区间去「凑」一个对不上的引文。

## 3. 引文（quote）判定

- 比较前会压缩空白（连续空格、换行、全角空格），并把弯引号归一为直引号；
- **措辞必须逐字一致**，不做同义改写、不做大小写忽略、不做翻译；
- quote 不必是整句，但必须是段落的连续子串；
- 空 quote 视为未解析；
- 引文长度建议 20–200 字符：太短（如 `the`）会到处命中，太长容易跨段而失败。

## 4. 失败时的最小修法

| 现象 | 原因 | 修法 |
|---|---|---|
| `anchor 's09.p09' does not match any paragraph` | 章节或段号不存在 | 回到 `sections.json` 找真实段号 |
| `quote not found in s03.p02` | 引文被改写/跨段/来自图表 | 从该段原文复制连续子串，或换到正确段 |
| `anchor … has an empty quote` | 只写了锚点没写引文 | 补 quote |
| `no anchor given` | 字段/条目没有锚点 | 为该条目补 `anchor` + `quote` |

## 5. 一级章节与覆盖

「一级章节」取所有章节中**最小的 level**（`#` 为 1，`##` 为 2）。若整篇都用 `##`，
则四个 `##` 章节都属于需要覆盖的集合。`section_summaries` 为每个一级章节提供一条摘要；
缺一条即 `section_uncovered`。

## 6. 偏移字段

`sections.json` 中每个章节有 `start/end`（全文绝对字符偏移），每个段落同样有 `start/end`。
它们用于把 `sNN.pMM` 快速映射回原文，不参与语义判断。
